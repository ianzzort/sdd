# Memory.md — Change History

This file is the memory of the SDD architecture. It keeps the history of every
change. The history helps you understand why the project is in its current
state.

## Rules

- Add a new entry at the top of the list after each change.
- Never delete an old entry. The history must stay complete.
- Write the date in the time zone of the project (see `Documentation.md`).
- Keep each entry short. One idea per line.
- If this file does not exist, create it with this same format.

## Entry format

```
## <date> — <short title>
- Change: <what changed, in one sentence>
- Files: <the main files or folders that changed>
- Skills used: <the skills that ran, or "none">
- Graph updated: <yes, no, or n/a>
```
